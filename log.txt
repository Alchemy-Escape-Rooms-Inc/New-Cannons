=== ROOT CAUSE FOUND: retained RESET on broker (2026-06-24) ===

THE REAL BUG (not the firmware, not a live publisher):
- A RETAINED "RESET" message was stuck on MermaidsTale/Cannon2/command on the broker
  (10.1.10.115). Confirmed via: mosquitto_sub -t MermaidsTale/Cannon2/command --retained-only
  -> printed "RESET".
- Retain lives on the BROKER, not the board. The broker replays the retained RESET to ANY
  client the instant it subscribes. So every Cannon2 boot -> subscribe (main.cpp:601) ->
  broker delivers retained RESET -> onMqttMessage RESET handler -> ESP.restart() -> reboot ->
  repeat, every ~2-4s. Explains "different board, same problem" (poison is on broker) and why
  reflash/power-cycle didn't help.
- PROOF on serial (COM18 capture, scratchpad/cannon2_serial.txt): boots, "[Watchtower] RESET
  -> Rebooting...", rst:0xc (RTC_SW_CPU_RST = software reset, NOT watchdog/panic), loops.
  Uptime never climbs (12618ms -> reboot -> 4330ms -> reboot ...).
- The June 7-8 broker logs showed a HEALTHY board (5-min heartbeats, uptime climbed to ~44h,
  0 reboots) -- the retained RESET wasn't there yet then. The "171x" was a hardcoded human
  note in build_master_timeline.py:415, NOT a measured reboot count. Disregard it.

FIX APPLIED:
1. Cleared the retained RESET: mosquitto_pub -t MermaidsTale/Cannon2/command -r -n (empty +
   retain = delete retained). Verified gone. Cannon1/command, Cannon2/reset, Cannon1/reset
   also confirmed clean.
2. Found existing cleaner: Desktop\EscapeRoom Pirate Original\clear_retained_mqtt.py.
   - main("all") = CURATED lists (GLOBAL/PIRATE/JUNGLE/COVE). These intentionally SKIP
     .../command and .../reset (treated as "device state"), so they could NEVER clear the
     retained RESET. THIS was the gap.
   - wildcard_wipe() DOES delete every retained topic incl. /command (empirically verified:
     planted retained RESET on MermaidsTale/ZZTest/command, ran `clear_retained_mqtt.py
     wildcard`, confirmed deleted).
3. START_ESCAPE_ROOM.bat step [6.5/10] was calling `clear_retained_mqtt.py` with NO ARG
   (= curated). Changed to `clear_retained_mqtt.py wildcard` so every game start fully wipes
   retained state, including any stray retained command/reset. (Edit + comment added in .bat.)

KNOWN WEAKNESS (not fixed, noted): wildcard_wipe() only discovers retained topics with
payload>0 during a quiet-period window (max_wait_s=10s) + one re-scan. A very large/laggy
retained set could let a straggler slip past. Fine for the current ~10 topics; bump max_wait_s

=== HARDENED the wildcard wipe so game start deletes EVERYTHING reliably (2026-06-24) ===

User goal: every restart/game-start must delete ALL retained topics, no exceptions.

Hardened wildcard_wipe() in clear_retained_mqtt.py to remove two ways it could miss topics:
  1. Removed the `len(msg.payload) > 0` discovery filter. It made retained ZERO-BYTE payloads
